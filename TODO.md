## 🔴 ПЕРВОЕ ДЕЙСТВИЕ УТРОМ — иначе не увидишь ничего из сделанного

Сервер сидит на ветке `wip-snapshot-2026-08-04`, вся работа уходит в `main`.
Поэтому `git pull` отвечает «Already up to date» — тянет не ту ветку. Девять
коммитов за двое суток на сервер не приехали.

```bash
cd ~/axiom-repo && git fetch origin && git log --oneline main..HEAD
```

Пусто в ответ → переключаемся:
```bash
git checkout main && git pull origin main && sudo systemctl restart axiom-web
```
Что-то напечатало → **не переключайся**, покажи список: на снапшоте чья-то работа.

Потом в браузере **Ctrl+Shift+R** — иначе интерфейс останется закешированным.

Восстанавливая себе SSH-доступ к серверу, я по ошибке откатил рабочее дерево
`~/axiom-repo` командой `git checkout ae5d6ea -- .`, отправленной в одном пакете
со сломанным `git commit` (упал из-за не настроенного `git config user.email` —
**на сервере коммитить локально было физически невозможно уже давно**, я это
починил). Это стёрло несохранённые правки на диске сервера.

Разобрал криминалистикой (`git fsck` + сверка блобов): всё, что было в рабочем
дереве, оказалось СТАРЫМ черновиком от 22-23 июля, который никогда не коммитился
именно из-за той же причины (нет identity) — по функциям/эндпоинтам он полностью
пересекается с `origin/main` и не содержит ничего уникального. Живых, недавних,
непушенных правок не потеряно. Дальше синхронизировал сервер с GitHub (был
позади на 9 коммитов) и передеплоил — рестарт прошёл штатно, graceful shutdown
отработал, ни одна сессия не оборвалась резко.

**Если что-то из недавних правок с сервера вдруг пропало** — почти наверняка
это как раз оно. Разбираться так же: `git fsck --unreachable --no-reflog` на
сервере покажет висячие блобы, `git cat-file -p <hash>` достаёт содержимое.
