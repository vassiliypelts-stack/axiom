# ТЗ — модуль исследования Telegram-групп (AXIOM)

> Модуль для 70 прогреваемых аккаунтов: за 3 месяца исследовать базу ~13 000 групп,
> разложить по полочкам, заодно прогреть аккаунты. Отделить зёрна от плевел.

---

## 1. Цель

Обойти базу из ~13 000 групп силами 70 аккаунтов за ~90 дней (3 месяца). По каждой группе
снять структурированную карточку (тип, открытость, активность, мусорность, тематика,
ключевые запросы), дать рейтинг 1–5 и встроить это в прогрев аккаунтов. На выходе —
фильтруемая аналитика: «группы по бизнесу с открытыми чатами», «рейтинг 1–2 — работаем»,
«мусор/мёртвые — архив».

---

## 2. Входные данные

- База групп: **~13 000** ссылок/username.
- Аккаунты: **70** (userbot, MTProto/Telethon/GramJS).
- Срок: **~90 дней (3 месяца)** — спокойный темп, меньше палива.
- Смежный модуль прогрева (лайки, комментарии, ЛС) — накладывается на исследование.

---

## 3. Математика и распределение

### Расчёт (основной сценарий — 3 месяца)

| Параметр | Значение |
|---|---|
| Групп на аккаунт за 3 мес | 13 000 / 70 = **186** |
| Групп в день на аккаунт | 186 / 90 = **2.1 ≈ 2** |
| Дневной диапазон | **1–4** (среднее 2.5) |
| Покрытие при 1–4 | 2.5 × 90 × 70 = **15 750** (+21 % запас) |
| Членство на аккаунте к концу | 186–225 групп (лимит ~500 выдержан) |

**Вывод:** 2 вступления в день на аккаунт — телега это не палит, лимит 500 сущностей
на аккаунт не задеваем (суммарно ~186–225 групп). Запас +21 % закрывает закрытые/мёртвые.

### Альтернатива (быстрый — 1 месяц)

13 000 за 30 дней → **6.2 групп/день** на аккаунт, диапазон **4–9** (среднее 6.5) →
13 650 групп (+5 %). Риск палива выше, лимит 195/аккаунт — тоже в пределах 500, но
темп заметно агрессивнее. Основной — 3 месяца.

### Запас обязателен

Часть из 13 000 — закрытые группы (не вступить), удалённые/приватные каналы,
чаты без активности. Реально «исследуемых» — 80–90 %. Запас +21 % это покрывает.

### Закрепление (шардинг)

- Каждая группа закрепляется ровно за **одним** аккаунтом (unique assign).
- 13 000 групп делятся на 70 аккаунтов → по **186 групп на аккаунт**.
- В системе всегда видно: `группа ↔ аккаунт` (карточка группы хранит assigned_account).
- Повторные/недоступные группы помечаются и не занимают слот другого аккаунта.

---

## 4. Процесс исследования одной группы (сценарий)

1. Аккаунт открывает группу по ссылке.
2. Фиксирует **тип** и **доступность** до вступления (канал / чат / чат-комментариев).
3. Если нужен чат — вступает (для канала вступление не обязательно).
4. Снимает статические поля (название, описание, счётчик, открытость участников, админы).
5. Снимает активность: N сообщений за последний месяц, частота, повторы.
6. Классифицирует тематику + извлекает частые вопросы/ключевые запросы (LLM).
7. Ставит рейтинг 1–5 и мусорность.
8. Прогрев (выборочно): лайк, нейтральный комментарий, при цели — ЛС участнику.
9. Пишет сводку-карточку в базу, помечает статус `done`.
10. Решение по членству: остаться (прогрев) или выйти (не грузить лимит).

---

## 5. Что снимать по группе (полная карточка)

### 5.1 Тип и доступность
- `type`: канал / группа (чат) / супергруппа / группа-форум / чат-комментарии при канале.
- `is_open`: открытая / закрытая (нужен инвайт/модерация).
- `can_post`: открыта для публикации или закрыта (важно для постинга).
- `link` / `username`.

### 5.2 Базовые поля профиля
- `title` — название.
- `description` — что написано в профиле.
- `participants_count` — количество участников.
- `participants_visible` — участники видны или спрятаны (**критично**).
- `admins` — кто админы, сколько, видны ли (снимать отдельно).
- `city/geo` — город/регион (из описания или переписки, если определяется).
- `created_at` — дата создания (если доступна).

### 5.3 Активность и качество
- `msg_per_day` / `msg_per_month` — средняя частота сообщений.
- `spam_score` — мусорность (0–100): доля повторяющихся/рекламных сообщений.
- `is_dead` — мёртвая (много участников, но 0–2 сообщения за месяц).

### 5.4 Классификация (LLM)
- `category[]` — 1 или несколько: бизнес, нетворкинг, региональная, отраслевая, прочее.
- `frequent_questions[]` — частые вопросы людей за последний месяц.
- `key_queries[]` — ключевые запросы по группе (для будущего таргета/контента).
- `summary` — короткая сводка по группе.

### 5.5 Рейтинг (1–5, финал)
| Рейтинг | Смысл | Действие |
|---|---|---|
| **1** | открытая, живая группа | рабочая база |
| **2** | открытая, полуживая | рабочая база (дожим) |
| **3** | мусорная | на усмотрение |
| **4** | мёртвая / спам | архив / удалить |
| **5** | группа уже не существует | удалить из базы |

Отдельно от рейтинга фиксируем флаг `can_post` (закрыта/открыта для публикации) —
это свойство группы, а не её рейтинг.

## 6. Прогрев (накладывается на исследование)

Один аккаунт в группе выборочно:
- вступает (сам факт = прогревочный сигнал);
- ставит 1–2 лайка на сообщения;
- изредка пишет нейтральный комментарий (не в каждой группе);
- при целевом участнике по критериям — пишет в ЛС (отдельная задача, не массовая).

Принцип: **не все действия в каждой группе**, иначе палится. Прогрев распределяется
по всему объёму 3 месяцев, аккаунт «живёт» естественно.

**Политика членства:** остаёмся в группах (не выходим) — суммарно к концу аккаунт
состоит в ~186–225 группах, это далеко до лимита ~500. Выход нужен только если группа
оказалась 3–5 рейтинга и не нужна для дальнейшей работы.

---

## 7. Антидетект (чтобы Telegram не палил)

- **Рандомное число групп в день** в диапазоне 1–4 (не фикс «2 каждый день»).
- **Рандомные паузы** между заходами в группы (напр. 1–6 часов — темп неспешный).
- **Перемешивание времени активности** по часовому поясу (не строго по будильнику).
- **Чередование действий**: вступил → иногда лайк → редко комментарий → пауза.
- **Членство под контролем**: 2 группы/день × 90 дней ≈ 186 групп на аккаунт —
  далеко до лимита ~500 сущностей. Лимит вступлений в день (обычно ~50) не задеваем.

## 8. Схема данных (таблица `groups`)

| Поле | Тип | Что хранит |
|---|---|---|
| id | int | ключ |
| link / username | text | ссылка на группу |
| title | text | название |
| type | enum | channel / group / supergroup / forum / comment_chat |
| is_open | bool | открытая/закрытая |
| can_post | bool | можно ли публиковать |
| participants_count | int | участников |
| participants_visible | bool | видны ли участники |
| admins | json | админы (кто/сколько/видны) |
| description | text | описание |
| city/geo | text | город/регион |
| category | json[] | тематика |
| msg_per_day | int | активность |
| spam_score | int 0–100 | мусорность |
| is_dead | bool | мёртвая |
| frequent_questions | json[] | частые вопросы |
| key_queries | json[] | ключевые запросы |
| rating | int 1–5 | рейтинг |
| assigned_account | int | закреплённый аккаунт |
| status | enum | new / in_progress / done / archived / trashed |
| last_scanned_at | datetime | когда исследована |
| summary | text | сводка |

Прогрев логируется отдельно (таблица `account_actions`): joined / liked / commented / dm_sent + время.

---

## 9. Аналитика и работа с результатом

Фильтры на выходе:
- «бизнес + открытый чат + рейтинг 1–2» — рабочая база для постинга/лидгена;
- «рейтинг 3» — отдельно, решить вручную;
- «рейтинг 4» — закрыта для публикации, но годна для ЛС;
- «рейтинг 5 + is_dead + spam» — архив / удалить;
- срез по городу, тематике, видимости участников, активности.

---

## 10. Краевые случаи

- Закрытая группа (не вступить) → карточка с `is_open=false`, без участников/активности.
- Канал без чата → снимаем описание/счётчик/посты, без вступления.
- Группа удалена / ссылка битая → статус `trashed`, не тратим слот.
- Аккаунт получил рестрикт (flood/бан) → пауза аккаунта, его группы перебрасываются
  на свободные, лог инцидента.

---

## 11. Этапы реализации (предлагаемый порядок)

1. **Схема БД** (таблицы groups + account_actions) и модель закрепления групп за аккаунтами.
2. **Снятие статики** (тип/открытость/название/описание/счётчик/участники/админы).
3. **Активность и мусорность** (сбор последних сообщений, метрика повторов, is_dead).
4. **LLM-слой** (категория, частые вопросы, ключевые запросы, рейтинг 1–5, сводка).
5. **Прогрев + антидетект** (рандомизация, паузы, управление членством).
6. **Аналитика и фильтры** (срезы, экспорт, архив/удаление).

мёртвая-спам / не существует.*
