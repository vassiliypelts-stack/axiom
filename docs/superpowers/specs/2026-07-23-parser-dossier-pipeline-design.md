# AXIOM — Гармоничный конвейер: Парсер + Досье + Аутрич

> Единая цепочка лидгена: **найти → собрать → изучить (досье) → написать → встреча**.
> Проектируем целостно, чтобы разрозненные инструменты стали одним конвейером.

---

## 1. Общая картина — единый конвейер

```
[РАЗВЕДКА]      найти целевые чаты ИЖС (риелторы/загородка/застройщики)
     │          поиск по темам + ключам
     ▼
[КАТАЛОГ]       чаты в базу → анализ: активность, можно ли писать, админы
     │          (chat_scan)
     ▼
[СБОР]          парсинг участников / админов / активных авторов → книжка
     │          + сырьё для досье (harvest: их сообщения)
     ▼
[ДОСЬЕ]         AI-портрет каждого: боли/страхи/желания/пол/откуда/
     │          психотип + готовый крючок (enrich_person, Haiku)
     ▼
[МОНИТОРИНГ]    ОДИН слушатель по ключам → горячие запросы → «Запросы»
     │          (человек прямо сейчас ищет подрядчика/риелтора)
     ▼
[АУТРИЧ]        агент (Sonnet) пишет персонально по досье → Zoom  ← готово
```

Парсер **поставляет** людей, досье **изучает** их, аутрич **конвертит**. Три звена
одной цепи, а не отдельные утилиты.

## 2. Трек ДОСЬЕ физлица (телефон/TG → глубокий портрет)

Ключевой запрос: «по номеру или @username зайти в профиль и понять человека —
что за канал, что в био, что пишет, боли/страхи/желания, пол, откуда».

### Поток
```
ВХОД: телефон ИЛИ @username
   │
   ├─ 1. RESOLVE: телефон → TG-профиль (импорт контакта, get_entity)
   │        достаём: tg_user_id, имя, @username, есть ли фото
   │
   ├─ 2. СБОР СЫРЬЯ:
   │        • bio профиля (описание о себе)
   │        • аватар → анализ фото (пол, возрастная вилка, дресс-код)
   │        • ЛИЧНЫЙ канал человека (если указан в профиле) → его посты
   │        • сообщения в общих чатах (harvest → tg_user_posts)
   │
   ├─ 3. AI-ДОСЬЕ (Haiku, дёшево):
   │        боли · страхи · желания · интересы · психотип · как общаться ·
   │        сегмент · пол · город/откуда · score · цитаты · ГОТОВЫЙ КРЮЧОК
   │
   └─ 4. → карточка контакта (раздел «Досье») → доступно агенту при аутриче
```

### Что УЖЕ есть (enrich_person.py)
Поля: `pains, fears, desires, interests, psychotype, comm_style, best_time,
segment, score, quotes, rec_message, photo_analysis, summary, confidence`.
Источник сырья: `tg_user_posts` (сообщения из чатов, собранные через `--harvest`).

### Что ДОСОБРАТЬ
1. **Кнопка «Досье по телефону/@»** — ввод номера или юзернейма → resolve →
   сбор сырья → досье. Одним действием, без ручного harvest.
2. **Парсинг личного канала** человека — если в профиле указан канал, собрать
   его посты (там боли/желания видны ярче, чем в комментариях).
3. **Явные поля:** `gender` (пол), `city` (откуда) — сейчас размазаны по
   photo_analysis/segment, вынести отдельно.
4. **DaData-обогащение по номеру** (опционально) — если номер привязан к ИП/юрлицу.

## 3. Трек ПАРСЕР — унификация

### Проблема
Три механизма слушают чаты и дублируют друг друга:
- `chat_keywords.py` — поллинг по расписанию
- `listener.py` — реалтайм фон
- `tg_listener.py` — реалтайм H2 (консольный)

### Решение
**Один слушатель** (взять `listener.py` как основу — он с авто-реконнектом и
supervise), управляемый из UI: кнопки **Запустить / Стоп / Статус**, показ живых
аккаунтов-слушателей и счётчик находок. `chat_keywords` (поллинг) оставить как
запасной «догоняющий» проход по расписанию; `tg_listener` — удалить (дубль).

### Целевые чаты ИЖС (заготовка)
Стартовые ниши-ключи для разведки:
- **риелторы загородки:** «риелтор загород», «продажа участков», «земля ИЖС»,
  «загородная недвижимость», названия агентств
- **застройщики/подряды:** «строительство дома», «подрядчик ИЖС», «каркасный дом»,
  «газобетон», «фундамент под ключ»
- **горячие запросы клиентов:** «ищу подрядчика», «построить дом», «кто строит»,
  «посоветуйте строителей»

## 4. Авто-вступление в чаты (антибан)

Чтобы парсить и слушать закрытые группы — аккаунты должны в них состоять.
- Неспешно: **20-30 вступлений/день на аккаунт**, рандомные паузы.
- Только прогретые аккаунты (стадия 5+).
- Статус вступления в карточке аккаунта.
- С явным подтверждением оператора (не авто-массово вслепую).

---

## 5. Дедупликация

Один человек встречается в разных чатах. Ключ дедупа — `tg_user_id` (стабильный).
При сборе/досье: если `tg_user_id` уже в контактах — обновляем, не плодим дубли.
Сливаем источники (в каких чатах замечен) в одну карточку.

## 6. План сборки (по этапам, каждый самостоятельно ценен)

| # | Этап | Размер | Ценность |
|---|------|--------|----------|
| 1 | **Досье по телефону/@** — кнопка resolve→сырьё→портрет | 🟡 | Сразу видно человека |
| 2 | **Парсинг личного канала** в досье | 🟡 | Глубже боли/желания |
| 3 | **Единый слушатель + UI** (запуск/стоп/статус) | 🟡 | Убрать кашу из 3 слушателей |
| 4 | **Целевые чаты ИЖС** — заготовка ниш/ключей | 🟢 | Есть куда целиться |
| 5 | **Авто-вступление в чаты** (антибан) | 🟡 | Доступ к закрытым |
| 6 | **Дедупликация** по tg_user_id | 🟢 | Чистая база |

**Рекомендую начать с этапа 1** (Досье по телефону/@) — он самый «вау» для Василия
и переиспользует готовый enrich_person, нужна только обвязка resolve+сбор+кнопка.
