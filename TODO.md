## ✅ Закрыто 15-19.08 — почему аккаунты горели и почему бот писал не тем

- [x] **Найдена НАСТОЯЩАЯ причина сгоревших аккаунтов.** Telegram жжёт ключ не за
      параллельные подключения, а за подключения **с разных IP** (текст ошибки: «used
      under two different IP addresses simultaneously»). Проверка живости, не достучавшись
      через прокси, пробовала **напрямую с IP сервера**, пока слушатель держал ту же
      сессию через прокси. Ходит она по всем аккаунтам разом — отсюда гибель пачками.
      Теперь напрямую пробуем, только когда слушатель выключен.
- [x] **Запасная сессия** — вторая независимая авторизация через QR-механику Telegram,
      без SMS. Переживает ожог ключа: сгорела основная — поднимаем запаску кнопкой.
      Копия .session бэкапом НЕ является (тот же ключ, и параллельный запуск как раз
      сжигает). На 07.09 застрахованы ВСЕ 10 живых боевых (родные 3 — вне охвата).
- [x] **Защита новых аккаунтов на автомате** — раз в час сам ставит 2FA и выпускает
      запаску. Денег не тратит (смена номера через hero-sms в авторежим не входит).
      Тумблер «автозащита» в «Аккаунтах», включён.
- [x] **Бот заговаривал с кем угодно из базы.** Правило было «аккаунт active → отвечаем
      всем, чей contact_id нашёлся в книжке», а книжка полна людей из парсинга и импорта,
      которым мы ничего не слали. Теперь агент отвечает, только если кампания **фактически
      писала** этому человеку с этого аккаунта. Для родных номеров сверх того — аккаунт
      должен числиться в команде кампании **сейчас**.

- [x] **Можно писать самому из «Диалогов»** — поле под перепиской, уходит с того же

## ✅ Закрыто 07.09

      17 аккаунтов идёт дольше. Слушатель включался посреди прогона, хватал сессии,
      следующий промоут открывал по ним второе подключение. Воркер теперь продлевает
      метку паузы на каждом круге.
