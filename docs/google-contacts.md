# Google Контакты: выбор по маркерам в названии

В пульте: **Контакты → Google Контакты**. Введите маркеры через запятую,
например `эск2023, ск2025/2026`. Поиск не зависит от регистра и пробелов;
`ск2025/2026` раскрывается в `ск2025` и `ск2026`. Маркер ищется в любой части
названия, поэтому `ск2025` также находит `эск2025`. Список можно уточнять любыми
другими маркерами длиной от трёх символов.

1. Нажмите «Найти в Google» после подключения или загрузите экспорт Google CSV.
2. Отметьте людей, выберите один телефон у каждого, проверьте имя для обращения.
   Исходное название из Google сохраняется в `name`, обращение — в `person_name`.
3. Выберите новый черновик или кампанию на паузе с отдельным тегом аудитории.
4. Нажмите «Добавить выбранных». Настройка и запуск рассылки остаются в «Кампаниях».

Это выборочный односторонний импорт по запросу. Повторный поиск перечитывает
Google; фоновой синхронизации и обратной записи в Google нет. Новые контакты
из Google не добавляются в кампанию без выбора оператора. Удаления из Google
не удаляют карточки AXIOM. Предпросмотр живёт 30 минут и теряется при рестарте.

## Подключение Google

Доступ к календарю не включает контакты. Используется отдельный файл
`axiom/google_contacts_token.json` с разрешением `contacts.readonly`.
Файл исключён из git; сервер принимает его только после проверки через Google.

1. В проекте Google Cloud включите **People API**.
2. Используйте OAuth-клиент **Desktop** либо добавьте
   `http://localhost:8765/` в Authorized redirect URIs существующего Web-клиента.
   Скачайте JSON клиента после изменения. Существующие redirect URI календаря сохраните.
3. На компьютере оператора установите зависимости проекта и выполните:

   ```powershell
   python axiom/tools/google_contacts_login.py --credentials "путь-к-файлу-клиента.json"
   ```

4. Разрешите чтение контактов в открывшемся Google. Полученный файл загрузите
   в **Контакты → Google Контакты → Подключение → Загрузить файл доступа**.

Если подключения пока нет, экспортируйте контакты в **Google CSV** и загрузите
его в этой же панели. Поддерживаются старые (`Name`, `Given Name`) и новые
(`First Name`, `Last Name`) заголовки, несколько телефонных колонок.

API читает все страницы `people.connections.list`, а не поиск по префиксу:
маркер часто записан в конце имени. Документация:
[People API](https://developers.google.com/people/api/rest/v1/people.connections/list).

## Изоляция и повторный импорт

Дубли сопоставляются по нормализованному телефону (`8 916…` и `+7 916…` равны).
История и поля существующей CRM-карточки сохраняются. Контакты не в статусе `new`,
тестовые, удалённые и закреплённые за другой кампанией пропускаются с причиной.
Неоднозначные дубли в существующей базе автоматически не сливаются.

Добавляемое миграцией поле `contacts.outreach_campaign_id` ограничивает выбранные
контакты одной кампанией. Кампании с пустым тегом и старые CLI-отправщики их не
подхватывают. Старые контакты с NULL продолжают отбираться как раньше.
Работающие кампании нельзя выбирать при импорте; новый черновик создаётся с
выключенным автозапуском. Токены, сессии аккаунтов и настройки рассылок импорт не меняет.

## Проверки

Из `axiom/`: `python -m unittest discover -s tests -p test_google_contacts.py -v`.
Проверки работают с временной SQLite и подменённым Google API, не отправляют сообщения.
